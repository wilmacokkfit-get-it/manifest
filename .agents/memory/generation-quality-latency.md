---
name: Generation quality and latency
description: Why faster reasoning is opt-in rather than the production default
---

Keep medium reasoning as the default until a repeatable comparison demonstrates
both latency benefit and preserved explicit constraints. Measure first visible
text separately from completion; do not equate a valid JSON object with a good
idea.

**Why:** A fixed synthetic comparison made low reasoning faster, but its venture
added subscriptions despite an explicit prohibition. Earlier roughly 74-second
and 20-second observations were not controlled and cannot prove a regression.

**How to apply:** Use bounded, opt-in, text-only comparisons with fixed inputs.
Never create real ventures or images merely to benchmark text. Read outputs for
intent and internal consistency before lowering reasoning or shortening quality
guidance. Communicate unknown saved state honestly when a connection fails
during a potentially successful commit.
